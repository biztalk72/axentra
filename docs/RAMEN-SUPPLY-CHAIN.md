# 라면 공정과 업종 공용 공급망

기본 업종은 라면이다. A라인은 배합·반죽 → 압연·절출 → 증숙·건조 → 완제품 포장, B라인은 스프 배합 → 분쇄·체질 → 정량 충전 → 스프 소포장으로 구성한다. 설비 8대, 품목 14개, 창고 위치 6개, 다단계 BOM 5개를 제공한다. 일반 공정의 개념은 [농심 라면백과](https://www.nongshim.com/promotion/ramyun_pedia/pedia)를 참고했다. 배합 수량·공정 수치·품질 상태는 체험용 가정이며 상용 레시피나 HACCP 검증 결과가 아니다.

## 공용 도메인과 에이전트

| 공용 기능 | 원장과 실행 규칙 | 에이전트 진단 |
|---|---|---|
| 품목·인벤토리 | 원재료/반제품/완제품/포장재, 기준 단위·최소재고 편집 | 사용 승인·기한 유효 재고, 최소재고 미달 |
| 분류 | 위치별 허용 분류, 잘못된 적치 제한 | 분류 규칙과 재고 위치 불일치 |
| 창고 | 창고/구역/로케이션 등록·편집, LOT별 수불 | 사용 중인 위치·보류 재고. 물리적 적재 용량 추정 아님 |
| 물류 | 입고·이동·출고, 가상 AMR·현장 요청 연계 | 이동 원장·요청·대기 로봇 |
| LOT | 검사 대기/사용 승인/차단, 제조일·선택적 기한, 공급처 | 보류·기한 경과·기한 임박 및 다단계 계보 |
| BOM | 구성품·산출량·버전 편집, 순환 금지 | BOM별 기준 배치 소요량·부족량 |

기존 13개에 공용 inventory/classification/warehouse/lot/bom 5개를 추가해 공용 18개, 라면 전용 noodles/soup 2개로 구성한다. 업종·지원 화면·데이터 제품 메타데이터가 카탈로그에 있다. 코드와 매개변수·의존성·리비전을 개별 관리한다. 에이전트는 읽기 전용 진단을 수행하며 자재 변경은 아래 업무 API와 권한을 따른다.

## 운영 흐름

1. 관리자가 품목·위치·BOM을 등록한다. 이미 사용한 품목의 단위를 바꾸거나 현재 재고를 무효화하는 분류 규칙 변경은 거부한다.
2. 운영자가 입고한다. 새 LOT는 검사 대기이며 관리자 승인 전에는 투입·출고할 수 없다. 검사 대기 LOT도 적합한 격리 위치로 이동할 수 있다.
3. BOM 생산에서 산출량을 입력하고 **소요량·FEFO LOT 할당 확인**을 누른다. 승인·기한 유효 LOT 중 기한이 먼저 도래하는 재고를 추천한다. 미리보기는 쓰기를 하지 않는다.
4. **검토한 LOT 투입·생산 입고**로 원재료 차감, 완제품 검사 대기 입고, 생산 배치의 BOM 스냅샷, 수불 원장과 연동 이벤트를 같은 트랜잭션에 기록한다. 부족·잘못된 할당·낡은 BOM이면 모두 취소한다.
5. LOT 추적에서 원재료 → 면/스프 → 소포장 → 라면 → 출하 박스의 상·하위 계보와 간선을 확인한다. 하위 배치의 함께 투입된 원료도 조회한다. 승인 후 출고한다.

kg은 소수 셋째 자리, ea/box는 정수로 처리한다. Python Decimal과 Pages BigInt로 수량을 계산한다. 단위가 다른 재고를 합산하거나 kg↔ea를 임의 환산하지 않는다. 수량·품목·위치 검증 후 동일 event_id 재시도는 한 번만 반영하며, 같은 ID의 다른 내용은 충돌로 거부한다. PostgreSQL의 원장 행 잠금으로 동시 차감의 음수 재고를 방지한다.

현재 단일 사업장 MVP는 공급망 상태를 하나의 JSON 원장 행에 보관한다. 대규모 도입에는 정규화된 원장·예약·피킹/패킹·실사 조정·다사업장·성능 설계가 추가로 필요하다. BOM은 품목당 활성 버전 하나와 생산 당시 스냅샷을 제공한다. 다단계 반제품 생산은 단계별 명시 실행하며 자동 MRP 재귀 생산·예약·수율/스크랩·레시피 승인·식품 중요관리점 제어는 후속 범위다.

## 업종 전환과 데이터 보존

**공정·재고·창고 → 업종·공정 설정**에서 라면/일반 제조 템플릿, 공장명, A/B라인명·공정 단계를 편집한다. 전환은 표시와 에이전트 호환성을 변경하며 재고·LOT·BOM·사용자·감사·기존 실행을 삭제하거나 새로운 업종 데이터로 덮어쓰지 않는다. 라면 전용 에이전트는 일반 제조에서 새 실행·설치 대상에서 제외하며 기존 위젯에는 사용 중지 상태를 표시한다.

기존 합성 CNC/조립 설비 세트가 그대로 있는 환경만 한 번 라면 설비 ID로 이관한다. 이벤트 FK·활성 작업 참조는 함께 바꾸고 기존 진단 스냅샷·감사는 보존한다. 이전 합성 설비를 참조하는 진행 중 진단은 일시중지 후 새 진단이 필요하다. 실제 현장 고유 설비를 추정해서 이름을 바꾸지 않는다.

## 대시보드·현장 설치

운영 대시보드의 **위젯 설치·설정**에서 현재 업종에 호환되는 에이전트를 최대 4개 설치하고 A/B 기준 라인을 정한다. 개인 계정별 저장이다. 공용 공급망 재고는 공장 전체이며 라인 선택으로 별도 재고가 생기지 않는다.

패널 스튜디오의 **에이전트 위젯**에서 최대 4개를 선택하고 순환 화면에 **공용 에이전트 현황**를 넣는다. 초안 미리보기 → 저장 → 관리자 게시의 기존 절차와 일괄 배분을 사용한다. 장치 키는 게시된 읽기 전용 결과를 패널 스냅샷에서만 받으며 관리·재고 API 접근 권한을 얻지 않는다. 결과는 선행 모듈을 한 번씩 실행한 스냅샷이며 LLM·자재 변경·장비 명령을 실행하지 않는다.
