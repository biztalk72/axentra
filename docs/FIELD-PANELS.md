# 현장 패널 운영

오피스 콘솔의 **현장 패널 스튜디오**에서 라인별 TV 전광판과 작업자 터치 패널을 구성한다. `UI-sample/`의 대형 생산 지표·설비 카드·작업 타일 구성을 참고해 독립 구현했다. 참조 이미지 자체는 배포하지 않는다.

## 화면과 배포

생산 현황, 설비 상태, 품질, 작업 지시, Andon 지원 요청, 물류, 공지, CCTV의 8개 템플릿을 제공한다. 패널마다 1~12개 화면의 순서·제목·표시 시간(10~300초)·메시지와 자동 순환을 설정한다. TV/터치, 밝은/어두운 테마, 4개 해상도(세로형 포함), 갱신 간격(5~60초)을 지원한다.

1. 패널을 선택하거나 등록하고 라인·설치 위치를 지정한다.
2. 재생 목록과 같은 라인의 CCTV 위젯을 구성한다. 미리보기에서 화면을 전환하고 게시본과 비교한다.
3. **초안 저장** 후 관리자가 **게시**한다. 초안 편집은 설치 화면을 변경하지 않는다.
4. 여러 패널 선택 → **선택 패널에 구성 배분**은 화면·테마·순환 설정만 복사한다. 각 대상의 라인·위치·해상도·카메라 연결은 유지한다. 일괄 게시도 별도 관리자 작업이다.
5. 게시 화면 열기로 독립된 현장 화면을 확인한다. 전체 화면·자동 순환 일시정지·수동 전환을 지원한다.

단건·일괄 저장과 게시는 `expected_revision`을 검사한다. 충돌은 409로 반환하며 일괄 작업은 모두 성공하거나 모두 롤백한다. 미리보기는 공통 렌더러를 사용하지만 입력·게시·하트비트를 발생시키지 않는다. 패널별 연결 표시는 실제 하트비트가 있을 때만 갱신된다.

## 설치와 권한

운영자는 등록·초안 편집·미리보기, 관리자는 게시와 장치 키 발급까지 수행한다. 조회자는 읽기·미리보기만 가능하다. 실제 API는 모든 권한을 다시 검사한다.

관리자가 패널의 **설치용 연결**에서 30일 키를 발급한다. 원문은 한 번만 반환하며 서버에는 SHA256 해시를 저장한다. 새로 발급하면 이전 키는 즉시 무효다. 설치 URL은 `/#panel/PANEL-ID?key=...`이고 첫 로드에서 fragment의 키를 sessionStorage로 이동한 뒤 주소에서 제거한다. 키는 그 패널의 게시 화면 읽기·하트비트·허용된 터치 입력에만 사용할 수 있다. 오피스 구성이나 다른 패널에는 접근할 수 없다. 브라우저 탭을 닫거나 키가 만료되면 다시 연결한다.

터치 패널의 작업 확인과 설비·자재·품질 지원 요청은 게시된 화면 종류 및 같은 라인의 작업을 검증하고 감사 기록을 남긴다. `event_id` 재전송은 중복 입력을 만들지 않는다. 작업 확인은 생산 실적 완료나 PLC 제어를 의미하지 않는다.

**GitHub Pages는 브라우저 체험이다.** 저장소와 키도 해당 브라우저에서만 유효하므로 실제 다른 장치에 배포하려면 공통 API에 연결한 Docker 버전을 사용한다. 오프라인에서는 마지막 수신 화면과 연결 지연 안내를 표시하며 정상 연결로 표시하지 않는다.

## 데이터 해석

작업 달성률은 진행 작업의 완료/목표, 품질은 설비 누적 양품/(양품+불량)이다. 누적 공정 처리량을 완제품 생산량이나 OEE로 표시하지 않는다. 생산 추이는 최종 공정의 최근 수집 증분을 사용한다. 물류 로봇은 사업장 공용 가상 AMR이며 라인에 귀속된 실로봇이 아니다. 세부 API는 [API 계약](API.md)을 따른다.
